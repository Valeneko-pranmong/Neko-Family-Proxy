In scope:

  updates, and clean-start installation.

Out of scope:

- Any 5.1.6 account, day, or coupon transfer.
- Stable publication or `releases/latest`.
- Control Room admin web auth and 5.3.0 legacy shutdown.
- Authenticode signing (still pending an operator certificate).

## Evidence

Record:

- Alpha tag, commit SHA, release ID, and asset SHA-256/size.
- Installer build record and the staged preview profile hash.
- Staging bridge deployment ID and migration list (no secrets).
- Sanitized screenshots/notes for version identity, web-only login, and
  preview-only update discovery.
- Pass/fail for every test-matrix row and the failure paths.
- Any alpha feedback that changes scope; do not include tokens, passwords, or
  private-key material.

## Exit criteria

- Every staging test row passes.
- No 5.1.6 breakage or stable-feed contamination.
- A new account can complete web-only login and launch; a preview update can
  apply safely.
- Open defects are triaged with owners; any release-blocking defect pauses the
  alpha.
- Owner decides whether to continue the preview, fix forward with `5.2.0a2`, or
  pause.

## Rollback

- Within the alpha line: publish a higher-sequence preview or have testers
  uninstall/reinstall the alpha; never copy old files or downgrade in place.
- To return to the stable line: uninstall the alpha and install 5.1.6 cleanly;
  local state is not migrated.
- If the feed is wrong: remove the prerelease from discovery, keep 5.1.6 as
  latest stable, and do not promote any 5.2.x tag.

## Publication rule

Do not tag, publish assets, enable production web auth, or promote any 5.2.x
release to stable until the staging and owner gates above pass.
