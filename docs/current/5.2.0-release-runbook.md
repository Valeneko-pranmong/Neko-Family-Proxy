## 6. Staging E2E

Use a real staging identity and a linked proxy account with an active license:

1. Discord login through the Launcher.
2. `/v1/me` returns the active account and license.
3. Claim returns `session_id`, heartbeat interval, and license validity.
4. Heartbeat succeeds at the server-provided interval.
5. `/v1/launch-permit` returns a permit and Runtime Config v1.
6. Core starts with the permit and the proxy connects.
7. Release on exit succeeds.

Negative cases:

- suspended/banned account -> no token or no launch;
- missing app role -> authorize denied;
- expired or inactive license -> claim/permit denied;
- second installation claim -> latest-claim-wins and displaced session gets
  `session_conflict`;
- ambiguous refresh -> token cleared and interactive login required;
- wrong audience/scope -> 401/403.

Verify no Supabase URL/key/session, no bridge call, and no proxy database
access in the new-line process, logs, and network traffic. Record redacted
status codes, request/correlation IDs, deployment IDs, permit verification
result, and Core start/exit evidence. Never record tokens, permits, runtime
credentials, or keys.
