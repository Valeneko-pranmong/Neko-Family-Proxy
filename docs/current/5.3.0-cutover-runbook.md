# Neko Family Proxy Legacy Retirement Runbook (formerly 5.3.0 Cutover)

> **Release-label superseded (2026-10-25):** `5.3.0` is not a release label.
> The first usable release of the unified line is **5.2.0** (preview, clean
> uninstall-first). This document is retained only as the future
> legacy-retirement checklist for `5.1.6`; it is not the 5.2.0 release
> runbook. Use [5.2.0-release-runbook.md](5.2.0-release-runbook.md) for the
> 5.2.0 build, install, E2E, and rollback path. Do not publish under a 5.3.0
> label.

**Scope:** retire the legacy 5.1.6 password/recovery line and make the
unified line the only supported product.

**Status:** prepared; not executable until the P1/P3/P4 gates and owner
approval are complete. This runbook must not be used to mutate production
before that approval.

## 1. Hard preconditions

- [ ] P1 staging E2E passed: loopback -> identity -> bridge -> Supabase session
      -> next-line claim/heartbeat/permit -> Core start.
- [ ] Auth `session_id` stability across refresh is verified, or allowlist
      rotation is implemented.
- [ ] Control Room admin web auth is complete and password admin login is no
      longer required.
- [ ] Account recovery API is retired or replaced; no password-reset consumer
      remains.
- [ ] P3 installer ISCC rebuild and install/uninstall matrix passed with 5.1.6
      installed/running and 5.2.0 reinstall.
- [ ] P4 preview release/auto-apply evidence passed.
- [ ] All shared-auth consumers are re-audited against the recorded inventory.
- [ ] Encrypted backups and a tested restore process exist.
- [ ] Owner approves the cutover date and the no-transfer/cutoff policy.

Do not proceed if any item is open.

## 2. Freeze the legacy line

- Stop new 5.1.6 signups.
- Stop legacy renewals and sales.
- Stop legacy coupon issuance and redemption; publish the unused-coupon notice
  and void date.
- Keep existing 5.1.6 login/claim/heartbeat/permit working until its current
  term expires or an explicit cutoff is approved.
- Announce 30/14/7/1 days before shutdown.
- Do not delete legacy data while any active term remains.

## 3. Retire non-Launcher consumers

### Control Room admin

- Move operator access to the approved Control Room admin web auth.
- Remove password admin login from the active route.
- Verify admin session creation, logout, role checks, and unauthorized denial.
- Keep a break-glass support procedure separate from customer password auth.

### Account recovery API

- Stop the legacy recovery-code/password endpoint.
- Verify no client version or support tool still calls it.
- Remove recovery secrets/functions after the retention window.

## 4. Publish the unified release

1. Freeze the source commit and build the approved Launcher/Updater/Core bundle.
2. Build the installer with the approved configuration and the current
   preview trust profile.
3. Verify hashes, signature, installer gates, and `--self-check`.
4. Run the install matrix and a clean-machine smoke test.
5. Publish the unified preview release after all gates pass; do not use a
   5.3.0 label.
6. Verify login, claim, permit, Core start, and update discovery.
7. Retire the preview channel only after the unified release is verified and a
   separate owner decision authorizes it.

## 5. Legacy shutdown

Only after the last active legacy term expires or an explicit cutoff is
approved:

1. Revoke legacy refresh tokens, launcher sessions, and active licenses.
2. Export the legacy reconciliation record: user/license hash, term, cutoff,
   migration/closure status, operator where applicable.
3. Archive payment, audit, coupon, and consent records per retention policy.
4. Verify the archive checksum and restore test.
5. Disable legacy password provider/access and drop legacy schema/RPCs/functions
   after the retention and rollback window.
6. Revoke/delete legacy keys and environment secrets.
7. Remove the legacy installer links and update support documentation.
8. Record the final shutdown evidence and owner approval.

## 6. No-transfer policy

- Do not transfer 5.1.6 days or unused coupons to a 5.2.0 account.
- Do not silently revoke paid days.
- Legacy users remain on 5.1.6 until expiry or the approved cutoff.
- Unused legacy coupons become void only after the published notice period.
- Keep a reconciliation record so support can verify a closed entitlement.

## 7. Verification checklist

- [ ] 5.1.6 has no active license/session at shutdown.
- [ ] No password/recovery consumer remains.
- [ ] Control Room admin web auth passes.
- [ ] Unified release assets verify.
- [ ] Unified-line E2E passes.
- [ ] Legacy data archive/restore passes.
- [ ] Old keys/secrets are revoked.
- [ ] Support runbook and customer notices are published.
- [ ] Rollback window has passed before deletion.

## 8. Rollback

- Stop the cutover; do not delete legacy data before the rollback window.
- Restore the legacy service from the verified backup if a paid-term or
  activation defect is found.
- Keep the release artifact and evidence; do not republish old stable assets.
- Re-run the affected gate before retrying cutover.

## 9. Do not

- Do not transfer days/coupons without a new owner decision.
- Do not delete active legacy terms.
- Do not expose recovery/password credentials in support channels.
- Do not disable the legacy provider before the last active term/cutoff.
- Do not claim Authenticode signing unless the certificate/evidence exists.
