## 3. Unified-line architecture

5.2.0 is the first usable release target of the unified line:

```text
Discord browser
  -> Neko-NETWORK-ID /launcher/authorize + /api/launcher/token
  -> Launcher (access token in memory, refresh token in Windows Credential Manager)
  -> Neko Proxy API /v1/me, /v1/session/*, /v1/launch-permit, /v1/coupons/*
  -> NekoProxyCore (fresh permit + Runtime Config v1 over the existing pipe)
```

The new line:

- authenticates through Neko-NETWORK-ID only;
- reads and writes proxy-domain state through Neko Proxy API only;
- stores no Supabase URL, key, session, cookie, PostgREST client, or proxy
  database credential in the Launcher process;
- does not call `launcher_bridge`, mint a Supabase session, or use the
  `launcher_v2.web_sessions` allowlist;
- keeps the Core request, permit, and Runtime Config v1 contract unchanged.

The legacy bridge, Supabase gateway, and `launcher_v2` artifacts remain in the
repository only because 5.1.6 still needs them. They are not part of the 5.2.0
runtime path.

### Control Room dependency

The Launcher's public proxy-status display still reads the existing Control Room
endpoint. Migration to Proxy API `/public/status` is deferred; the Control Room
endpoint must remain available for 5.2.0. This is a known 5.2.0 dependency, not
a hidden fallback.

## 4. What is new in 5.2.0

- Discord browser login with loopback callback, PKCE S256, state validation,
  identity access token, and a rotating refresh token.
- Proxy API account preflight (`/v1/me`), session claim/heartbeat/release, and
  launch permit plus Runtime Config v1 through the frozen Core pipe.
- Fail-closed refresh: any failed or ambiguous refresh clears the stored token
  and requires a new interactive login. Sign-out is local-only until a
  revocation endpoint exists.
- Server-provided heartbeat interval (10–60 seconds) and stale-session handling.
- Thai error mapping for every shared Proxy API and identity error code.
- Refreshed Launcher, authentication, Dashboard, and Settings presentation.
- Atomic committed-generation self-sync, buffered support/debug logging, and a
  one-shot startup update check.
- Pinned Core manifest, `Redirector.bin`, and `nfdriver.sys` during elevated
  driver registration, with the redirector loaded from an administrator-only
  staging directory.
- Per-user launch-permit rate limiting, pinned CI action SHAs, and Pillow
  13.0.0 for image-parsing CVE remediation.
- New update trust anchors: release key `neko-update-prod-2` and profile
  authority `neko-update-profile-v520-1`. The preview profile authorizes only
  that release key.

## 5. Installation (clean uninstall-first)

1. Decide whether you still need 5.1.6. If you need its remaining days, stay on
   5.1.6. There is no transfer to 5.2.0.
2. Back up any local preferences you need. Uninstalling 5.1.6 removes its
   launcher state, trust, baseline, tools, ProxyCore, logs, and local JSON/path
   files from `%LOCALAPPDATA%\NEKO FAMILY`.
3. Close Neko Family Proxy, any active proxy session, and PSO2.
4. Uninstall **NEKO FAMILY PROXY 5.1.6** from Windows Settings > Apps.
   The shared netfilter2 driver is intentionally preserved.
5. Confirm the 5.1.6 installation is gone. Do not force-install 5.2.0 over a
   partial tree.
6. Run the approved 5.2.0 installer. It must refuse to install while a
   Launcher/Core/Updater process is running or while a different installed
   version remains.
7. Sign in through Discord. Verify Settings > About shows `v5.2.0`.
8. Start PSO2 through the normal flow.

## 6. Rollback to 5.1.6

Rollback is a clean reinstall, not a downgrade:

1. Uninstall 5.2.0. Its local state, trust, baseline, logs, and program files
   are removed.
2. Install the frozen 5.1.6 installer from the canonical release source.
3. Sign in with the 5.1.6 account credentials. The legacy account remains on
   the legacy backend; it was not migrated or changed by 5.2.0.
4. Do not copy 5.2.0 tokens, trust files, or state into the 5.1.6 installation.

Rollback does not restore 5.2.0 local preferences, and it does not transfer any
5.2.0 state back to 5.1.6.

## 8. Known limitations and deferred work

- Coupon redemption is implemented in Neko Proxy API but not integrated into
  the Launcher.
- `/public/status` migration to Neko Proxy API is deferred; the Control Room
  endpoint remains a dependency.
- The legacy bridge, `launcher_v2`, and Supabase code remain for 5.1.6 and are
  not removed in 5.2.0.
- Sign-out and refresh revocation are local-only while contract v0 has no
  identity revocation endpoint.
- There is no in-place upgrade from 5.1.6, no side-by-side installation, and
  no automatic update from 5.1.6 to 5.2.0.
- No Authenticode signature is available.
- A frozen 5.2.0 build cannot currently enable `NEKO_PROXY_API_URL`; the
  release configuration gate must be resolved with an owner-approved HTTPS
  origin before a usable installer can be built.
