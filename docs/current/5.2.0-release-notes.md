# Neko Family Proxy 5.2.0 — Release Notes

- **Release line:** `v5.2.0`
- **Date:** 24 October 2026
- **Channel:** preview/manual (must not be published as the latest stable while 5.1.6 is supported; final channel decision pending)
- **Release sequence:** `14` (`stable-0014`) — revalidate if the preview moves to a separate channel/sequence
- **Upgrade type:** separate 5.2.0 preview line. 5.1.6 remains on 5.1.6 until the 5.3.0 cutover; anyone moving to 5.2.0 must uninstall 5.1.6 first.
- **Policy revision:** 2026-10-25 — 5.1.6 and 5.2.0 are separate installation and authentication lines. The install-over guidance in earlier drafts is withdrawn.
- **Candidate status:** the 2026-10-25 local build passed before the web-auth and Core clock-skew changes; final candidate rebuild and publication are pending. The artifact hashes below are superseded. The current source still contains password fallback; 5.2.0 is not releasable until the web-only and separation gates in the cutover plan pass.

## สำคัญที่สุด: 5.1.6 กับ 5.2.0 แยกกันโดยสมบูรณ์

v5.2.0 เป็นสายใหม่ที่ใช้ web auth 100% และแยกจาก 5.1.6 ซึ่งยังใช้ password/recovery กับ legacy backend ตามเดิม การเปลี่ยน trust anchor ทำให้ 5.1.6 ไม่สามารถ auto-update ไป 5.2.0 ได้ และเราไม่ต้องการให้ผู้ใช้ 5.1.6 ถูกกระทบระหว่างพัฒนา 5.2.0

- ผู้ใช้ 5.1.6 ที่ยังต้องการใช้งาน **ไม่ต้องทำอะไร**; 5.1.6 ยังใช้งานได้จนถึงการ cutover เป็น 5.3.0
- ผู้ใช้ที่ต้องการใช้ 5.2.0 ต้อง **uninstall 5.1.6 ก่อน** แล้วจึงติดตั้ง 5.2.0
- ห้ามติดตั้ง 5.2.0 ทับ 5.1.6 และห้ามให้ทั้งสองเวอร์ชันอยู่ด้วยกัน
- 5.2.0 จะไม่ถูกส่งเป็น auto-update ให้ 5.1.6
- การ uninstall จะลบ state, trust, logs และไฟล์โปรแกรมของ 5.1.6; ถ้าต้องการเก็บ settings ให้สำรองเอง เพราะ 5.2.0 เริ่มจาก clean state
- 5.2.0 preview เปิดเฉพาะบัญชีใหม่; ไม่มีการโอนวันคงเหลือหรือ coupon จาก 5.1.6 — อย่า uninstall 5.1.6 หากยังต้องใช้สิทธิ์จนหมดอายุ

> ห้ามพยายามติดตั้งทับหรือคัดลอกไฟล์ข้ามเวอร์ชัน และไม่แนะนำให้ downgrade กลับ 5.1.6 หลังติดตั้ง 5.2.0 แล้ว ให้ใช้ uninstall/reinstall แบบสะอาดเท่านั้น

## What's new

### Fresh launcher experience

- ปรับ visual system ใหม่ทั้ง Launcher, หน้าเข้าสู่ระบบ, Dashboard และ Settings โดยใช้โทน rose/plum ที่อ่านง่ายขึ้น
- ปรับการ์ดสถานะ, connection diagram, membership card, ปุ่ม, ช่องกรอกข้อมูล และ navigation ให้มีลำดับชั้นชัดเจนขึ้น
- คง flow หลัก: Discord web login, dashboard แบบ read-only, Settings แยกหน้าต่าง และสถานะแบบ truthful ไม่สร้างตัวเลขปลอม; 5.2.0 ไม่มี recovery/password flow (5.1.6 ยังมีบน legacy line)

### Security and reliability

- เพิ่ม atomic self-sync: ตรวจ SHA-256 ของ executable ที่จะใช้แทนตัวเอง เขียนไฟล์ชั่วคราวแบบ fsync แล้วสลับด้วย atomic rename พร้อม rollback
- ลด write amplification ของ support/debug logs ด้วย line-buffered handles แทนการเปิดไฟล์ใหม่ทุกบรรทัด
- ตรวจ startup update check เพียงครั้งเดียว เพื่อไม่ให้ schedule ซ้ำ
- Pin manifest, `Redirector.bin` และ `nfdriver.sys` ในขั้นตอน elevated driver registration และโหลด redirector จาก staging directory ที่เฉพาะ Administrator/SYSTEM เข้าถึง
- เพิ่ม per-user rate limit 10 ครั้ง/60 วินาทีสำหรับ `issue_launch_permit` (HTTP 429 `RateLimited`)
- Pin GitHub Actions เป็น full commit SHA และปิด credential persistence ใน checkout
- อัปเกรด Pillow เป็น 13.0.0 เพื่อแก้ CVEs ด้าน image parsing
- ลดขนาดแพ็กเกจ Launcher จากประมาณ 35 MB เหลือประมาณ 27 MB และปิด UPX เพื่อลด false positive จาก antivirus
- NekoProxyCore ผูก control และ telemetry named pipes กับ Launcher PID ที่แน่นอน
- Core ทน clock skew ได้ไม่เกิน 10 นาทีเฉพาะเมื่อ challenge ยังสดและถูกใช้ครั้งเดียว; นาฬิกาปกติยังตรวจ 2 วินาที/30 วินาทีแบบเข้ม และ skew เกิน 10 นาทียัง fail closed
- 5.2.0 ตั้งเป้าเป็น web-auth-only: Launcher มี browser/Discord login (loopback + PKCE S256 + state + bridge session) แล้ว แต่ source ปัจจุบันยังมี password fallback และ flag `NEKO_WEB_AUTH_ENABLED`; ต้องถอด password/recovery ออกจาก 5.2.0 และปิด flag path ก่อน publicação

### Update trust rotation

- Release key ใหม่: `neko-update-prod-2`
- Profile authority ใหม่: `neko-update-profile-v520-1`
- Trust profile ที่ลงนามแล้วอนุญาตเฉพาะ release key ปัจจุบัน
- Public key เดิมยังคงอยู่ในไคลเอนต์เพื่อตรวจสอบ release เก่า แต่ไม่ได้รับอนุญาตให้เซ็น release ใหม่
- Private keys เก็บไว้นอก repository ใน custody directory ของเครื่องผู้ดูแล; ต้องสำรองออกสื่อภายนอกแยกต่างหาก

## Installation

1. ตัดสินใจว่าจะอยู่บน 5.1.6 ต่อหรือเริ่มบัญชีใหม่บน 5.2.0; 5.2.0 preview ไม่รับบัญชี 5.1.6 เดิม และหากยังต้องใช้สิทธิ์คงเหลือให้อยู่บน 5.1.6 จนถึง 5.3.0
2. สำรองการตั้งค่า/ข้อมูลที่จำเป็น เพราะ uninstall 5.1.6 จะลบ state, trust และไฟล์โปรแกรมใน `%LOCALAPPDATA%\NEKO FAMILY`; 5.2.0 เริ่มจาก clean state
3. ปิด Neko Family Proxy, proxy session และ PSO2
4. Uninstall **NEKO FAMILY PROXY 5.1.6** ผ่าน Windows Settings > Apps > Installed apps
5. ดาวน์โหลด `NekoFamilyProxy-Installer.exe` จาก canonical repository releases
6. ตรวจ SHA-256 ของ installer เทียบกับค่าที่ประกาศใน release ถ้ามีการประกาศ; ยังไม่มี Authenticode certificate ในรุ่นนี้
7. รัน installer 5.2.0; installer ต้องปฏิเสธหากยังพบ 5.1.6 หรือ process ที่กำลังทำงาน (guard นี้ยังต้อง implement ก่อน publicação)
8. เปิด Launcher, เข้าสู่ระบบด้วย Discord และตรวจ version ที่ Settings > About
9. เปิด PSO2 ตาม flow ปกติ

## Known limitations

- 5.1.6 and 5.2.0 are separate installation lines; in-place upgrade and side-by-side installation are not supported.
- Existing 5.1.6 clients cannot auto-update to 5.2.0 and must not receive it as a stable update.
- The 5.2.0 installer source now enforces the running-process guard and exact-version guard (including blocking 5.1.6). The rebuilt installer and install/uninstall matrix are still pending.
- The current source still contains password/recovery fallback; 5.2.0 must remove it and pass web-only tests before publication.
- Discord web auth is implemented but disabled; the proxy bridge, identity→proxy mapping, one-time link/claim flow, and staging E2E are not complete.
- The identity staging bridge and test accounts are not available yet.
- The 5.2.0 release-channel separation from the 5.1.6 stable feed is not implemented/tested.
- 5.2.0 is new-accounts-only; there is no transfer of 5.1.6 accounts, remaining days, or unused coupons. Legacy 5.1.6 stays usable until the existing term expires or an approved cutoff.
- Authenticode code signing is still pending an operator certificate.
- The permit rate-limit migration must be applied before the matching Edge Function is deployed.
- The previous installer hash table is from the pre-web-auth/Core-clock checkpoint; rebuild and re-hash before publication.
