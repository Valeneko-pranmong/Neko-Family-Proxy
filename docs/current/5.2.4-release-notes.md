## Summary

5.2.4 contains the 5.2.3 login and coupon fixes plus the updater fix that makes
future in-app updates possible again.

A 5.2.2/5.2.3 installation **cannot auto-update to 5.2.4**. Those users must run
the 5.2.4 installer once (uninstall the old version first). After that, future
5.2.x updates work normally.

## Why 5.2.3 could not update 5.2.2

The 5.2.2 updater validates the installed Core with the canonical manifest
schema (`rid` / `executable` / `files[]`). The frozen 5.2.0 Core authority uses
the legacy manifest schema (`file_count` / `files{}` map), so every apply failed
with `CORE_INVENTORY_INVALID` before any file was replaced. The check runs
inside `NekoUpdater.exe`, so changing the release feed alone could not fix it.

5.2.4 rebuilds the updater with support for both schemas:

- canonical schema: unchanged
- frozen 5.2.0 authority schema: validates `source_commit`, `file_count`,
  every declared SHA-256, mandatory files, and rejects unlisted files

The updater artifact is now pinned for the rest of the 5.2.x line. Future
releases must ship the same `NekoUpdater.exe` bytes until the updater can
replace itself safely.

## Customer-visible changes

- Discord login works on first use; a pending proxy account shows **0 days**
  until a coupon is redeemed.
- Coupon redemption in Settings calls `POST /v1/coupons/redeem`, activates the
  account, adds days, and refreshes the session.
- `NEKO FAMILY NETWORK ID` keeps the same Discord login; no app-role grant is
  required first.
- No change to ProxyCore, the proxy connection, or the PSO2 game flow.

## Manual migration from 5.2.2 / 5.2.3

1. Close Neko Family Proxy, the proxy session, and PSO2.
2. Uninstall the old version from **Windows Settings > Apps > Installed apps**.
3. Download `NekoFamilyProxy-Installer.exe` from the v5.2.4 release.
4. Run the installer and wait for the Core and .NET steps.
5. Open the launcher and sign in with Discord again.
6. Confirm Settings shows **5.2.4** and
   `%LOCALAPPDATA%\NEKO FAMILY\baseline\release-v2.json` is the `stable-0028`
   envelope.

Account days and entitlement are stored on the server; uninstalling does not
remove them. The local Windows Credential Manager entry is removed by the
uninstaller, so the Discord sign-in is required again.
